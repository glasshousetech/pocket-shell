# Pocket Shell 0.5.0: whole-app themes

The earlier theme picker changed ANSI text but left the app and translucent terminal backdrop unchanged. This release replaces fixed chrome colors with scoped Compose theme roles and explicitly paints the native terminal background. The selected theme also controls dialogs, key controls, and Android system bars. The window is opaque so phone wallpaper cannot reduce text contrast.

The picker offers twenty previews, text search, All/Dark/Light/OLED filters, an empty-search recovery action, and direct selection from either the workspace or Settings. A lazy adaptive grid fits narrow phones, landscape, and unfolded devices. Close remains outside the scrolling catalog.

The portable JSON source generates Android and CSS adapters. Existing palette IDs, preferences, ANSI colors, foreground service sessions, and SSH data are retained. Recoloring resets emulator palettes in place and uses the existing history-preserving redraw path. Startup loads the saved palette before the terminal service can create a session.

## Verification

The catalog validator checks role contrast and adapter freshness. Unit tests cover complete terminal palettes, historical preferences, fallback, and search. The hosted Android UI fixture drives all twenty themes with two live PTYs, checks native background and ANSI values in both sessions, reads back the saved selection, recreates the Activity, and verifies history remains anchored. The existing terminal, input, and workspace tests remain release gates.

Physical-phone installation and ARM64 SSH acceptance are separate from hosted emulator proof. Publishing an APK must not force-stop the user's active terminal session.

## History regression found during UI verification

The first hosted run applied all twenty palettes and preserved both PTYs, but the final history assertion failed (`topRow -12 -> 0`). The pinned Termux `TerminalView.updateSize()` unconditionally resets `mTopRow` when rows or columns change; a full-screen search dialog and its IME can resize the underlying Activity. The existing screen-output redraw guard cannot intercept this independent resize path. The library view is final, so `TerminalViewport.onLayout()` wraps its resize and carries the historical line across same-width resizes, compensating for rows moved between the visible screen and transcript, and clamps safely on reflow. Live-output and alternate-screen behavior remain unchanged. The same end-to-end history assertion gates the corrected build.

The corrected resize implementation passed hosted CI run `36523568953`: build/lint, 20 unit tests, and all 10 emulator tests (including all 20 themes, both live PTYs, preference restoration, history anchoring, landscape, and an unfolded viewport). The independent gallery check passed 360/420/1440 px selection, filtering, search, empty state, and overflow checks. A subsequent visual refinement adds a 4 dp horizontal terminal inset and makes the active-tab underline measure to its label width; the final commit is rechecked before release.

The byte and command-execution assertions remain intact; these changes do not alter shipped app code.

### Download verification lesson

The stable APK URL returned the correct release while the new immutable catalog URL returned HTTP 503 with `X-GHT-Download-Status: locked-pending-safety-review`. The existing Caddy software-download hold uses exact reviewed release exceptions; placing an APK under `/apps/` does not add one. For Connor's explicitly requested deployment, add only the tested artifact's exact path, back up and validate Caddy, reload, and verify both URLs. Preserve all other hold rules. Download metadata uses lowercase unseparated SHA-256 certificate digests even though the fingerprint helper prints uppercase colon-separated hex. Screenshots pulled from app-private storage also require public-readable file/directory modes before preview hosting; copying their original app-private modes causes HTTP 403.
